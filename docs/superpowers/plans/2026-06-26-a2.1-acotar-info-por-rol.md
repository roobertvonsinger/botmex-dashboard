# A2.1 — Acotar info por rol (que el dashboard no aviente de más) · Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development o superpowers:executing-plans. Steps usan checkbox (`- [ ]`).

**Goal:** Que los endpoints de listado (`cards/all`, `pass-map`, `combos`, `deposits`) entreguen a un operador solo SU universo de cuentas, no todas — para quitar fricción (foco, sin roces, no quemar recursos). El SA sigue viendo todo.

**Architecture:** Un helper único `_visible_emails(user, c)` define el universo del caller (SA → None = todo; operador → cuentas asignadas + las que tiene lockeadas). Cada endpoint filtra contra ese universo. Aditivo, sin cambiar contratos de respuesta. No es blindaje de seguridad — es higiene de información (los operadores son confiables; ver [[feedback_capas_operador_vs_backend]]).

**Tech Stack:** FastAPI + SQLite, pytest + TestClient.

## Global Constraints

- **NORTE frictionless:** acota lo que se entrega, no blinda contra ataques. Cero pasos extra para el operador.
- **Regla de universo (deducida del modelo de Robert, confirmable):** SA (`role=='superadmin'`) ve TODO. Operador (`admin`/`user`) ve solo: cuentas en `account_assignments` con su `user_id` ∪ cuentas con `locked_by` = su telegram_id (str) o su username. El pool publicado NO entra en credenciales (lo ve para ganchar en `/api/accounts`, pero sus tarjetas/combos solo cuando la gancha).
- **Sin enmascarar** lo que SÍ le toca ver (pipes puros, combos juntos — [[feedback_no_masking]]).
- Tests inyectan rol vía `app.dependency_overrides[require_session]` (el modo `open` del conftest fuerza SA; hay que override por test).

- [ ] **Step 4: Implementar el helper** en `app.py` (cerca de `_resolve_operator`):

```python
def _is_sa(user: dict) -> bool:
    return user.get("role") == "superadmin"

def _visible_emails(user: dict, c) -> set[str] | None:
    """Universo de cuentas que el caller puede ver. None = SA (sin restricción).
    Operador: asignadas (account_assignments) ∪ lockeadas por él."""
    if _is_sa(user):
        return None
    tg = int(user.get("telegram_id") or 0)
    uname = (user.get("username") or "__none__").lower()
    out: set[str] = set()
    try:
        for r in c.execute("SELECT email FROM account_assignments WHERE user_id=?", (tg,)):
            out.add(r["email"])
    except sqlite3.OperationalError:
        pass
    for r in c.execute(
        "SELECT email FROM accounts WHERE locked_by IN (?, ?)", (str(tg), uname)
    ):
        out.add(r["email"])
    return out
```

```python
@app.get("/api/accounts/pass-map")
def accounts_pass_map(user: dict = Depends(require_session)):
    """Mapa email→password acotado al universo del caller (SA = todos)."""
    with db() as c:
        vis = _visible_emails(user, c)
        rows = c.execute("SELECT email, password FROM accounts WHERE password IS NOT NULL").fetchall()
    return {r["email"]: r["password"] for r in rows
            if vis is None or r["email"] in vis}
```

`accounts_combos`:
```python
@app.post("/api/accounts/combos")
def accounts_combos(req: CombosRequest, user: dict = Depends(require_session)):
    if not req.ids:
        return {"combos": []}
    placeholders = ",".join("?" * len(req.ids))
    with db() as c:
        vis = _visible_emails(user, c)
        rows = c.execute(
            f"SELECT id, email, password FROM accounts WHERE id IN ({placeholders})",
            req.ids,
        ).fetchall()
    return {"combos": [
        {"id": r["id"], "email": r["email"], "password": r["password"]}
        for r in rows if vis is None or r["email"] in vis
    ]}
```
