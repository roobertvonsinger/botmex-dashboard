# Fixes 13-ago-2026 — Masacre de la misión 736c99ee

## Problema
Misión auto 736c99ee de Luisito (08:18-08:26 MX) quemó 15 intentos, 5 en jramales29 (kyc_verified=0) con reintentos infinitos por:
1. Bug de clasificación: `IsUserInValidationProcess` se confundía con "401/redirectLogin" → re-login infinito
2. Respaldo dinámico sin gate de KYC → cuentas sin verificación entraron al pool de respaldo
3. BEGIN_ERROR no terminal → reintento infinito de la misma cuenta

## Root Cause
- **Bug viejo (28-jun)**: `deposits.py:1181` hacía `if "redirectlogin" in low or "401" in low:` → el payload de error de BetMexico SIEMPRE incluye `'redirectLogin': False` → falso positivo de sesión muerta.
- **Cambio reciente (12-ago, opencode/Claude)**: respaldo dinámico en `auto_deposit.py:1176-1196` añadió cuentas sin filtrar por `kyc_verified`.
- **Falta de gate**: `select_accounts_for_auto` no valida `kyc_verified`.

## Solución aplicada

### 1. deposits.py — Clasificación correcta de IsUserInValidationProcess
- **Línea 1183-1198**: Añadido check ANTES del `redirectlogin/401`:
```python
if "isuserinvalidationprocess" in low or "the_transaction_does_not_comply" in low:
    err = f"Cuenta bloqueada por BetMexico (IsUserInValidationProcess) — no reintentar"
    # Persistir dead_reason para que futuras misiones no la tomen
    try:
        from app import db as _dash_db
        with _dash_db() as c:
            c.execute(
                "UPDATE accounts SET dead_reason='IsUserInValidationProcess', dead_at=? WHERE email=?",
                (datetime.now(timezone.utc).isoformat(), email)
            )
    except Exception as e:
        logger.warning(...)
    return {"fail": {"success": False, "result_code": "KYC_PENDING", ...}}
```
- Esto marca la cuenta como KYC_PENDING/DEAD y persiste `dead_reason`, evitando reintentos.

### 2. auto_deposit.py — Gate KYC en respaldo dinámico
- **Línea 1195-1210**: Añadido gate en el respaldo:
```python
if b_acc.get("kyc_verified") != 1:
    logger.info(f"➖ CUENTA DE RESPALDO SALTADA (kyc_verified≠1) | {b_email}")
    continue
```
- Solo cuentas con `kyc_verified=1` entran al respaldo dinámico.

### 3. auto_deposit.py — Marca dead_reason para cuentas bloqueadas
- **Línea 1158-1166**: Añadido branch para `code == "KYC_PENDING"`:
```python
if code == "KYC_PENDING":
    failed += 1; account_declines += 1; break
    # Persistir dead_reason para evitar futuros intentos
```
- Esto evita que la misión reintente la misma cuenta.

### 4. Base de datos — Marcar jramales29 como dead
- Manual: `UPDATE accounts SET dead_reason='IsUserInValidationProcess', dead_at='2026-08-13T14:26:53Z' WHERE email='jramales29@gmail.com';`
